Dovilo 2.0 · Model Context Protocol

The task list your coding agent works out of, from any machine

Dovilo gives AI coding agents an MCP task list of their own. Claude Code, Cursor and any other MCP client connect to dovilo.app/mcp/agents with a key you create in the app, and work only the AI tasks you write for them: never your own to-do list, and they cannot create or delete tasks. A second server, at dovilo.app/mcp, lets ChatGPT, Claude, Gemini or Grok propose plans and tasks that wait for your approval. Dovilo Desktop does not need to be running.

Two servers

One for agents that do the work, one for assistants that plan it

Both servers run at dovilo.app and speak MCP over Streamable HTTP. They are separate on purpose: a coding agent and a chat assistant get different credentials, different tools and different reach, so neither can borrow the other's access.

Getting started

Three steps to a working agent

Create a key, add the server to your client, write a task. The agent can run on your laptop, a server or a CI runner, and Dovilo Desktop does not need to be open.

1

Create the agent and its key

In the mobile app, open AI Agents and tap New agent: give it a name, pick the projects it may work on, and create its key. In Dovilo Desktop the same flow is Connect a new AI.

The key is shown once. Copy it into your client or your secret store straight away. If it is lost, regenerate it: the old key stops working right away.

You need Pro and Dovilo 2.0 or later. Pro starts with a 7-day free trial you begin in the iOS or Android app. What it costs after that.

2

Add the server to your client

Every client gets the same two things: the server URL and your key as a bearer token in the Authorization header. The app's connect flow has a preset for Claude Code, Cursor, Cursor CLI, Codex CLI, Gemini CLI, Windsurf and Claude Desktop, shows where each config goes, and fills in your key.

Claude Code, one command
claude mcp add --transport http --scope local dovilo https://dovilo.app/mcp/agents --header "Authorization: Bearer <API_KEY>"
Cursor, and most other MCP clients over HTTP
{ "mcpServers": { "Dovilo": { "url": "https://dovilo.app/mcp/agents", "headers": { "Authorization": "Bearer <API_KEY>" } } } }

Field names differ between clients: Windsurf calls the URL serverUrl, Codex CLI takes a TOML block, and Gemini CLI has its own mcp add command. That is why the presets exist; use the one for your client. Claude Desktop has no field for a custom header, so its preset runs the server through mcp-remote, which needs Node.js on that machine. Claude Code can also keep the entry in a .mcp.json in the repository; that file holds the key, so the app reminds you to add it to .gitignore.

3

Write an AI task and hand it over

Agent work lives in its own place: create a project, write a short brief (goals, constraints, what to leave alone), then add the job in the AI Tasks tab, on the phone or on the desktop. That tab is the entire surface an agent can read. Your personal to-do list in My Tasks is never exposed to it, so nothing you keep there needs excluding.

Then ask your agent for the work in plain language. It discovers the tools on its own.

a session, abbreviated
> take my next Dovilo task and work it list_tasks → 3 queued in "Landing rewrite" get_task → "Split the pricing table by plan" (4 steps) read_context → project brief + constraints update_status → running update_step → 1 done · 2 done add_step → "regenerate the OG image" append_note → what changed and why append_telemetry → 41s · 18.2k tokens · $0.07 update_status → done

Every one of those lands on the task itself, so the AI Tasks tab on your phone shows the step trail, the notes and the cost while it happens. If the agent needs a decision it sets awaiting-user and stops. You answer from the task, the agent reads your reply with get_task and carries on, and the answer costs no quota.

Agents MCP · tool surface

Nine tools, and the ones that are missing

Three read, six write, and none of them create or delete a task. Every one of them works on AI tasks only, in the projects the agent's key is assigned to: the agent works the jobs you wrote for it, it does not read your to-do list and does not grow its own queue behind your back.

ToolAccessWhat it does
list_tasksreadLists the AI tasks in the agent's projects, with their status. A scheduled task stays out of it until its time comes. Personal to-do items are never in this list.
get_taskreadOne AI task in full: description, steps, notes, telemetry, and your latest reply if the agent asked you something.
read_contextreadThe project brief and the context that task carries: goals, constraints, conventions.
update_statuswriteClaims a task with running, then moves it to awaiting-user, done, done-with-errors or error. With cancelled and a reason, cancels a task the agent should not run.
update_stepwriteMarks a step in the plan as started, finished, failed or skipped.
add_stepwriteAdds a step the agent discovered along the way.
skip_stepwriteSkips a step that turned out to be unnecessary.
append_notewriteWrites a note onto the task: what it did, what it decided, what it could not do.
append_telemetrywriteReports model, tokens, cost and duration for the run.

What an agent cannot do

  • Read your personal to-do list. My Tasks is not on the tool surface at all.
  • Create a task, or delete one.
  • See AI tasks outside the projects its key is assigned to.
  • Pick up a scheduled task before its time.
  • Keep working after you revoke its key. It loses access right away.

New in 2.0

Tasks that open on time, and repeat

An AI task can wait for a set time before an agent sees it, and it can repeat. That makes the queue a place for recurring work too, not only for the job you hand over today.

Scheduled and repeating tasks

  • A task with a future start time has the status scheduled. Agents cannot see it until it opens; then it is queued like any other.
  • A task can repeat daily, weekly, monthly or yearly. Each run is its own task in the same series.
  • One open run per series. The next run is created when the previous one finishes, and occurrences missed in between are skipped, not queued up.

Cancelling, and the quota

  • An agent can cancel a task it should not run, with a reason: a queued task in its projects that nobody has claimed, or one it claimed itself. The task stays in your list as Cancelled. Cancelling is not deleting.
  • Pro includes 15 AI tasks a month. A task counts when it opens to the agent, not when you write it, and replies on the same task cost nothing.
  • Top-ups of +10, +30 or +75 tasks start at $0.99 and never expire.

Personal MCP

Plan in ChatGPT, approve in Dovilo

Personal MCP connects the chat assistant you already use, ChatGPT, Claude, Gemini or Grok, to your Dovilo account. It proposes; nothing lands in your lists or your agent's queue until you approve it on your phone.

Connect an assistant

  1. In the assistant, add a custom connector (some apps call it a custom MCP server) with the URL https://dovilo.app/mcp.
  2. Sign in with your Dovilo account, Google or Apple, and approve the consent screen.
  3. In Dovilo, open Connected AI apps to choose what it can see.

Each vendor documents where the setting lives: ChatGPT, Claude, Gemini, Grok. Availability depends on the vendor's plan and region. In the app, How to connect under Connected AI apps walks through each one.

What the assistant can do

list_lists list_tasks create_plan create_task update_task complete_task list_projects create_agent_task list_agent_tasks get_agent_task reply_agent_task update_agent_task cancel_agent_task

Thirteen tools: read your visible lists, propose a plan or a task, propose edits and completions, and, if you allow it, follow your AI tasks and draft replies to your agent. There is no delete tool, ever.

Per connection you control read access, whether changes need your approval (they do by default), which lists and projects are visible, AI task access (off by default), and revoke. Sending a plan works on Free; approving it, and everything else, needs Pro.

From a chat to a finished task

  1. Plan in ChatGPT. It proposes an AI task under one of your Dovilo projects.
  2. Approve it on your phone.
  3. Claude Code picks it up and works it.
  4. If it stops with a question, ChatGPT shows you the question and drafts an answer.
  5. Approve the answer, and the agent carries on.

Outbound

Signed webhooks for everything that isn't an agent

Webhooks are optional. Nothing in the MCP path needs them: an agent connects, reads its task and reports back without a single signed request. This section is the other direction. MCP is how an agent reaches in; webhooks are how Dovilo reaches out, to Slack, Linear, n8n, a LangGraph app, or your own service.

The contract

  • task.created, task.status_changed (carries previousStatus, which can be scheduled), and webhook.ping from the test button.
  • X-Dovilo-Signature: t=<unix ms>,v1=<hex>: HMAC-SHA256 over {t}.{rawBody}, 5-minute replay window.
  • X-Dovilo-Delivery is stable across retries: use it as the idempotency key.
  • Up to 5 retries at 5s, 30s, 2m, 10m, 1h. FIFO per task.
  • Answer an invalid signature with 401, never 410. 410 Gone disables the subscription.

Full reference, with verification code →

Who delivers

Public HTTPS receivers: Dovilo's server, even when Desktop is closed. The signing secret is generated on the server, stored encrypted and shown once.

Local receivers (localhost, private network ranges, .local): Dovilo Desktop, which must stay open. The app labels these Local.

Payloads are slim; an agent fetches the rest with get_task. The LangGraph demo is that loop, end to end, in code you can run.

Upgrading

Coming from Desktop 1.8

Desktop 1.8.0 ran the MCP server inside the app, so the agent had to run on the same machine. With Dovilo 2.0 that server stops, and agents connect to dovilo.app instead.

  1. Update Dovilo Desktop to 2.0 or later. It updates itself, and shows a banner, Move to remote MCP.
  2. Create a key for each agent, as in step 1.
  3. In each client, replace the old Dovilo entry with the server URL and the new key, as in step 2. An agent still set up the old way gets an error that explains the switch.

Straight answers

Questions you would ask before connecting

How hard is this to set up?

Two steps. Create an agent in the app (AI Agents, then New agent; in Desktop, Connect a new AI), pick its projects and copy its key. Then add https://dovilo.app/mcp/agents to your client with the key as a bearer token: one command for Claude Code, a short config entry for the other clients, and the app shows the right one for each. The client is the only thing the agent's machine needs, except Claude Desktop, whose preset runs through mcp-remote and needs Node.js.

Does Dovilo Desktop have to be running?

No. Since Dovilo 2.0, agents connect to Dovilo's server at dovilo.app, so they work from any machine whether Desktop is open, closed or not installed. Desktop is the desktop client: your to-do list and your AI tasks on a full-size screen, agent keys, and webhook setup.

Does any of this go through your servers?

Yes, since Dovilo 2.0. Agents and assistants connect to dovilo.app, which runs on Cloudflare and Google Cloud. We store only a hash of each agent key, and we process IP addresses and request details to protect the service and apply rate limits: rate-limit records are kept for up to 2 days, audit logs for up to 90 days. Anything your agent sends to its own model provider is governed by that provider's policy, not ours. The privacy policy has the detail.

Can an agent read my whole to-do list?

No. AI tasks and personal tasks are two separate surfaces in Dovilo. An agent reads the AI tasks of the projects its key is assigned to; nothing in My Tasks is on its tool surface, so there is no list to exclude and no filter to get wrong. A chat assistant on Personal MCP works differently: it sees the names of the lists you make visible to it, and their tasks only if you turn read access on.

Can an agent create tasks or delete my data?

No. Agents MCP has no create tool, and neither server has a delete tool. On the AI tasks it can see, an agent updates status, steps, notes and telemetry. It can also cancel a task it should not run, with a reason, and the task stays in your list as Cancelled. Revoking its key cuts it off right away.

What stops it touching the wrong project?

Its key. Each agent has its own key, tied to the projects you picked for that agent, and the check runs on every call. The project's brief defines what the agent is told about the work.

Does it work with something other than Claude and Cursor?

Yes. The connect flow has presets for Claude Code, Cursor, Cursor CLI, Codex CLI, Gemini CLI, Windsurf and Claude Desktop. Anything else that speaks MCP over HTTP connects with the URL and the key: a LangGraph app, a CI job, your own script. It is the open protocol, not a vendor integration.

Can ChatGPT or Claude change my tasks?

They can propose; you decide. A plan from ChatGPT, Claude, Gemini or Grok lands in the AI inbox on your phone with a notification, and joins your lists when you approve it. Plans, AI-task proposals and every change to an AI task always need your approval; other changes to your tasks wait for approval by default. There is no delete tool, and you can disconnect an assistant from your phone at any time.

Do I have to be at my desk to use it?

No. The agent can run on any machine, and AI Tasks is a tab in the mobile app too: write a task there, watch the agent move through its steps, read its notes and its token and cost telemetry, and answer its questions from the phone.

Can I get my data out?

Not yet. There is no export today, and it would be dishonest to imply otherwise. It is on the roadmap; the changelog is where it will show up when it ships.

Is this a real product or a weekend project?

It is a solo-built product, shipping regularly on four platforms. Releases are public in the changelog and on GitHub. There is no funding round behind it and no independent review of it yet; judge it from the release history and the demo repo.
