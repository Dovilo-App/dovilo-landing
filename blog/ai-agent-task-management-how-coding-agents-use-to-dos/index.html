By Selahaddin Akgün

AI agent task management is the practice of giving your coding agent a structured queue of work to pull from — so it can pick up, execute, and update tasks without you manually copying context from a to-do list into a chat window. If you use Claude Code, Cursor, or Windsurf to write code, you already know the friction: you keep a task list somewhere, and your agent knows nothing about it.

This article explains how that handoff works, what makes a to-do list actually usable by an AI agent, and how tools like Dovilo's MCP server solve the problem at the workflow level rather than the prompt level.

Why standard to-do apps break agent workflows

Most task managers are built for humans reading a list. They store text, maybe a due date, maybe a priority. That works fine when you are the one deciding what to do next.

An AI coding agent needs something different. It needs a defined surface it can query programmatically — a way to signal that it has started work, a way to mark something done, and ideally a way to post a result back. None of that exists in a typical to-do app, even good ones.

The result is a workflow that looks like this: you write a task in Notion or Todoist, open your terminal, paste the task description into a Claude Code session, then manually update the task when the agent finishes. Every step is manual. Every step breaks focus.

What an agent-ready task queue actually needs

For a coding agent to use a to-do list without human relay, the task surface needs to support at least four things.

Programmatic read access. The agent must be able to list tasks and read their details without a browser or GUI — that means an API or a local protocol the agent's runtime can speak.

Status updates. The agent needs to write back. "In progress", "done", "blocked" — whatever the schema is, the agent must be able to set it, not just read it.

Isolation from your personal list. You do not want an agent scanning your grocery list or your private notes. It should see only the work you have explicitly assigned to it.

A handoff mechanism. When the agent finishes a task, something should notify you. A webhook to Slack, a status change visible on mobile — something that closes the loop without you polling a terminal.

How the Model Context Protocol (MCP) fits in

MCP is an open protocol that lets AI agents communicate with external tools through a standardised interface. Instead of building a custom integration for every agent, a tool exposes a set of MCP-compatible endpoints and any MCP client can use them.

For task management, that means an agent running inside Claude Code or Cursor can call a "list tasks" tool, get structured data back, pick a task, mark it in progress, and post a result — all within the same session that is also writing code. No copy-paste. No context switch. The agent does not need to know anything about the app's UI. It just calls tools.

Dovilo's approach: a separate AI task queue on desktop

Dovilo runs a local MCP server on the desktop app (Windows and macOS, part of Pro). The server exposes nine tools split across read and update operations. The agent can read tasks, read project details, and update task status and results. It cannot create or delete tasks — that constraint is intentional. You define the work; the agent executes it.

The AI task queue is completely separate from your personal to-do list. When an agent connects to Dovilo's MCP server, it sees only the projects and tasks you have assigned to it. Your My Day list, your flagged items, your personal reminders — none of that is on the tool surface. The agent works from a dedicated queue, not your inbox.

Full MCP documentation is at dovilo.app/ai.

Which agents work with it

Dovilo's MCP server works with Claude Code, Claude Desktop, Cursor, Windsurf, Codex CLI, Gemini CLI, and any other MCP-compatible client you configure via JSON. No lock-in to a specific agent. If it speaks plain MCP, it connects.

How it runs locally

The server runs inside the desktop app over stdio. No Dovilo endpoint is involved — the only calls that leave your machine are the agent's own model calls. Task data stays local. That matters if you are working on proprietary code and do not want task context going through a third-party server.

Webhooks for closing the loop

When an agent updates a task, Dovilo can fire a signed webhook to Slack, Linear, n8n, or a custom endpoint. Set it up once, and every agent task completion posts a notification wherever you are watching. Webhook documentation is at dovilo.app/docs/webhooks.

Setting up an agent task in practice

Here is what the workflow looks like once the MCP server is configured:

  1. You create a project in Dovilo's AI task queue and write a brief for it. The brief is what the agent reads as context.
  2. You add tasks to that project with enough detail for the agent to act without asking follow-up questions.
  3. You open Claude Code — or Cursor, or whichever agent you use — and point it at the MCP server.
  4. The agent lists the tasks in the project, picks one, marks it in progress, and starts working.
  5. When it finishes, it marks the task done and posts a result. If you have a webhook set up, you get a Slack message or a Linear comment automatically.

You are not in the loop during steps 4 and 5. That is the point.

What Dovilo does not do yet

Two limitations worth knowing before you commit to a workflow.

No data export. You cannot currently export your task history or agent results to CSV or JSON. This is on the roadmap, but as of September 2026 it is not available.

No remote MCP. The MCP server runs where the desktop app runs. If your agent is running on a remote machine or a CI environment, it cannot connect to a Dovilo MCP server on your laptop — the agent and the desktop app need to be on the same machine. Remote MCP support is also on the roadmap.

If you run agents locally alongside your editor, neither limitation affects you. If you run agents in the cloud, remote MCP is a blocker for now.

How Dovilo compares to other task tools with agent support

A few other tools have moved toward agent-compatible task management, so it is worth being clear about what exists.

Todoist has an official MCP server at ai.todoist.net/mcp that gives agents access to your Todoist tasks. Pro is $5/month or $48/year. The key difference from Dovilo is that Todoist's MCP connects to your main task list, not a separate agent queue. There is no built-in isolation between personal tasks and agent tasks — you would need to manage that yourself with filters.

Linear supports agents natively, with tasks assignable to AI agents on every tier including the free plan. Linear is a team project management tool; Basic is $10 per user per month on annual billing. If you are a solo developer, it is often more tool than you need, but the agent support is real and well-built.

Blitzit is a to-do list and Pomodoro timer that also runs a local MCP server. It has logged over two million tasks and was voted Product Hunt's number one product of the day. It does not have gamification or a city-building reward layer, but if you want a lightweight MCP-connected task list without the game mechanics, it is worth evaluating.

The honest summary: Dovilo is not the only tool with MCP support. What it does differently is combine the agent task queue with a gamified reward system — completed tasks and focus sessions earn bricks, and bricks build an isometric city that grows as a visible record of real work done. That matters if you find standard task lists feel like admin rather than progress. It does not matter if you just want the plumbing.

The personal list and the agent queue stay separate

Worth repeating, because it is easy to assume otherwise. Dovilo has two distinct task surfaces. Your personal to-do list — with My Day, Planned, Important, and Flagged views, due dates, repeating tasks, and reminders — is for you. The AI task queue is for your agents. The agent never sees your personal list, and your personal list never gets polluted with agent output.

You manage your own work the way you always have. The agent works from what you assign it. The two do not interfere.
